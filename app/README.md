# helloo-app — auth (Better Auth + Hono on Cloudflare Workers)

The first slice of the helloo app: **authentication**, done the headache-free way. You own the users (in your own Postgres); you just supply keys. Email **OTP** + **magic link** + **social** (Google/GitHub/Apple) + **organizations** (for later workspaces) — all as config, no session/token code to write.

> Secrets live in `.dev.vars` (gitignored) and Cloudflare secrets — **never** committed. This folder is inside a public repo, so only `.dev.vars.example` (placeholder names) is tracked.

## 1. Install
```bash
cd app
npm install
```

## 2. Get a database (Neon Postgres — ~2 min)
Create a free project at **neon.tech**, copy the **pooled connection string**.

## 3. Configure keys
```bash
cp .dev.vars.example .dev.vars
```
Fill in `.dev.vars`:
- `DATABASE_URL` — the Neon string.
- `BETTER_AUTH_SECRET` — run `openssl rand -base64 32`.
- `BETTER_AUTH_URL` — leave as `http://localhost:8787` for dev.
- Social + email keys are **optional** (add later). **In dev, OTP works with no email key** — the code prints to the terminal.

## 4. Create the auth tables
```bash
npm run db:generate      # writes src/db/schema.ts from the auth config
npm run db:migrate:gen   # creates the SQL migration
npm run db:migrate       # applies it to Neon
```

## 5. Run it
```bash
npm run typegen          # generates worker-configuration.d.ts (bindings types)
npm run dev              # http://localhost:8787
```

## 6. Try it (no UI needed yet)
Request an OTP, then check your terminal for the code:
```bash
curl -X POST http://localhost:8787/api/auth/email-otp/send-verification-otp \
  -H 'content-type: application/json' \
  -d '{"email":"you@example.com","type":"sign-in"}'
# → the 6-digit code is printed in the `npm run dev` console (dev mode)

curl -i -X POST http://localhost:8787/api/auth/sign-in/email-otp \
  -H 'content-type: application/json' \
  -d '{"email":"you@example.com","otp":"THE_CODE"}'
# → sets a session cookie
```
Then `GET /api/me` with that cookie returns the signed-in user.

## 7. Add social login (optional, anytime)
Create OAuth apps (Google Cloud / GitHub Developer Settings / Apple), set the callback to `http://localhost:8787/api/auth/callback/<provider>`, and drop the client id/secret into `.dev.vars`. The provider turns on automatically. Sign-in URL: `/api/auth/sign-in/social` (`{ provider: "google" }`).

## 8. Turn on real emails (optional)
Add `RESEND_API_KEY` (resend.com) + a verified `EMAIL_FROM`. OTP/magic-link emails then send for real.

## 9. Deploy
```bash
# set each secret in Cloudflare (never in wrangler.jsonc):
npx wrangler secret put BETTER_AUTH_SECRET
npx wrangler secret put DATABASE_URL
# …and any social/email keys you use, plus set BETTER_AUTH_URL to your deployed origin
npm run deploy
```

## What's here
```
app/
  src/
    index.ts        Hono app — mounts Better Auth at /api/auth/*, plus /api/me
    auth.ts         Better Auth config: OTP + magic link + social + organization
    db/index.ts     Neon (edge) Postgres client via Drizzle
    db/schema.ts    generated by `npm run db:generate` (do not hand-edit)
    lib/email.ts    Resend sender (+ dev console fallback) and the env type
  better-auth.config.ts   CLI-only entry for schema generation
  wrangler.jsonc          Worker config (no secrets)
  .dev.vars.example       copy → .dev.vars (gitignored)
```

## Notes
- **Passwordless by design** — no password auth; OTP/magic-link/social only (matches helloo's "no re-explaining, low-friction" onboarding).
- The **organization** plugin is already wired for the Slack-style workspaces in v2.
- This is the backend/auth core. The **login/onboarding UI** is a separate, design-gated step — this exposes the endpoints it will call.
